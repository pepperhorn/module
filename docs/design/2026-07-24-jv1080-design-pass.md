# MODULE — JV-1080 Design Pass (2026-07-24)

**Audience:** implementing engineer with zero prior context on this codebase, strong React/CSS/Tailwind skill.
**North star:** MODULE should read unmistakably as a *light-colored* interpretation of a Roland JV-1080-class rack synth module — silkscreen legends, hardware controls, a backlit LCD, dense-but-legible function grouping — **without** cloning the dark charcoal faceplate. The app is and stays a light theme.

Reference photo: `/home/shaun/.claude/uploads/7f3adab9-7914-432b-bbf7-6f4277f681ba/1d9cb345-11429.jpg` (JV-1080 faceplate).

What makes the JV-1080 read as itself, decomposed:

1. **One continuous faceplate**, not floating cards. Controls sit *on* a single metal surface; grouping is done with silkscreened hairline boxes and printed group titles, not with separate raised panels.
2. **Tiny, disciplined silkscreen legends** — uppercase, condensed/mono, one consistent size and color, printed *on the panel next to* controls (above/below buttons), never inside them as web-button text.
3. **A small blue-green backlit LCD** in a recessed bezel — the only glowing, colored "screen" element. It is jewel-like precisely because everything around it is matte and quiet.
4. **Hardware controls with mechanical detail** — a big VALUE rotary with a knurled edge and position mark, small rectangular function buttons in tight ranks, LED indicators that are *tiny* and only glow when lit.
5. **Restrained color** — 95% of the faceplate is monochrome + legends; color appears only in a couple of accent legends (the orange "4x EXPANSION") and lit LEDs. Color = *state*, not decoration.
6. **Rack context** — ears, screws, model-number lockup ("SUPER JV · 64 VOICE SYNTHESIZER MODULE · JV-1080") that anchors it as a piece of equipment.

The current app already commits to several of these (see below). This pass closes the gap on the rest.

## 1. Design assessment — component by component

### What already works (build on it, don't discard)

- **The silkscreen legend idiom exists.** JetBrains Mono, uppercase, `tracking-widest`, tiny sizes are used everywhere (`ButtonBank.tsx`, `Rack.tsx` brand tag, `EffectsRow.tsx` chain header, `TouchKeyboard.tsx` header, `KeyboardHud.tsx`, `Lcd.tsx` rows, picker section titles). This is the single most JV thing in the app and it's deliberate. Keep it — but it's currently **undisciplined**: sizes wander across 9/10/11px and opacity across `text/40`, `/50`, `/55`, `/60`, `/65` with no system (compare `rack-bank-hint` 9px/40% in `App.tsx` vs `patch-picker-section-title` 11px/65% in `PatchPicker.tsx`).
- **The LCD exists and glows** (`Lcd.tsx` + `.lcd-glow` in `index.css`): dark navy field, scanlines, glowing patch number/name, OCT/VEL meta row. Structure is right (bank / number / name / meta). Hue and framing are wrong (see gaps).
- **Rack chassis with screws** (`Rack.tsx`): a max-width chassis with gradient, 4 corner `.rack-screw` radial-gradient screws, a brand strip with an LED brand mark. Good bones.
- **LED language is established**: `MidiStatus.tsx` (pulse via `.led-on`), `EffectPedal.tsx` bypass LED, `ConnectionStatus`, the brand mark. LEDs glow only when lit — correct instinct.
- **Knob and VALUE dial exist** (`Knob.tsx` conic-gradient arc ring + indicator; `ValueDial.tsx` 128px radial-gradient rotary with coral marker). Interaction (drag/wheel/shift-fine/double-click-reset) is solid; the *rendering* is what's generic.
- **The patch picker was just reworked** (labelled download pills, offline pill, mobile header). Do not regress it; only align its tokens.

### The 5 biggest gaps between "current" and "unmistakably a light JV rack module"

**Gap 1 — Floating web cards instead of one faceplate.**
`App.tsx` lays out `rack-panel` cards (`rounded-xl`, i.e. 12px radius) with `gap-4`/`mt-4` gutters between them, each with its own border + drop shadow, floating on the chassis gradient. The JV has *zero* floating panels: it is one surface with silkscreened group boxes. The current look reads as a tidy dashboard, not equipment. This is the #1 gap.

**Gap 2 — The LCD is the wrong hue and has no bezel.**
`--color-lcd-bg: #0F1024` (navy) with `--color-lcd-text: #5BC0EB` (the same sky blue used elsewhere in the UI). The JV LCD is distinctly **blue-green/teal** and that hue appears *nowhere else* on the faceplate — that exclusivity is what makes it read as a backlit display rather than "another blue element." The LCD also sits flat on the panel (`rounded-md p-4`, a soft drop shadow) with no recessed bezel/window frame, and at `minHeight: 120` + `text-2xl` it's more "hero card" than character display.

**Gap 3 — Buttons are web buttons, not function buttons.**
`ButtonBank.tsx` bank buttons and the PREV/NEXT/STAY ON/BROWSE/SAVE buttons in `App.tsx` are white-gradient rounded rectangles with their label *inside*, and the active state is a **full coral gradient fill with glow** — maximally web. On the JV, buttons are small blank (or near-blank) rectangles; the legend is silkscreened on the panel above/below; active state is a tiny LED, not a fill; groups are separated by hairline rules. `BROWSE LIBRARY` / `★ SAVE PATCH` as full-width glowing gradient bars are the most off-brand elements on the faceplate.

**Gap 4 — Color is decoration, not state.**
Eight candy accents (`--color-coral` … `--color-rose`) are applied as fills, gradients, colored headings (`effect-pedal-name` in pedal color), and glows on idle elements. The JV read requires: monochrome faceplate + graphite legends; **color reserved for lit LEDs, the LCD, knob position arcs, and one accent legend max**. The effect pedals (`EffectPedal.tsx`) are the main offender: colored title + colored LED + colored knob rings + white card = toy pedalboard, not rack FX section.

**Gap 5 — Legend typography fails its own job (and WCAG AA).**
The silkscreen legends at `text-text/40` on `#FAFBFC` blend to roughly `#A0A3AF` → **~2.4:1 contrast — fails AA** (4.5:1) badly; even `/50` fails (~3.2:1). 9px is also below comfortable legibility on 390px devices. The homage only works if the legends are crisp: JV silkscreen is *small but high-contrast*. Needs a real token (`--color-legend`) at AA contrast and a locked 2-size scale.

Secondary notes:
- `Rack.tsx` brand strip reads as a web app header (brand left, status pills + Sign In right). It should read as a faceplate lockup: brand + model designation + power LED, with the account/status cluster styled as panel hardware.
- `KeyboardHud.tsx` is a separate bordered footer card; on hardware this would be silkscreen printed along the bottom edge of the faceplate.
- `TouchKeyboard.tsx` is decent (dark keybed, recessed shadow) but the keybed floats inside another card, pressed-white-keys go full sky-gradient (loud), and there's no keybed "cheek"/frame detail.
- `ValueDial.tsx` has no knurling, no detent ticks, and a coral glowing marker — the JV VALUE knob is matte with a single position mark.
- Screws exist only at the 4 chassis corners; there are no rack ears, which is the cheapest, highest-signal JV cue available at desktop widths.

## 2. Target design language — "Light Rack" system

### 2.1 Surface & material

One continuous light faceplate; grouping by silkscreen frames, not elevation.

- **Page bed** (behind the chassis): keep `radial-gradient(ellipse at top, #FAFBFC 0%, #EDF0F4 100%)`.
- **Faceplate (chassis)**: near-flat brushed light alloy. `linear-gradient(180deg, #F2F4F7 0%, #E9ECF1 100%)`, border `1px solid #D4D9E0`, radius **10px** (down from 16px), shadow `0 10px 30px rgba(20,30,60,0.10), inset 0 1px 0 rgba(255,255,255,0.85)`. Optional: a barely-there vertical brush texture via `repeating-linear-gradient(90deg, rgba(255,255,255,0.28) 0 1px, transparent 1px 3px)` at ≤4% opacity overlay — skip if it moirés.
- **Group frame** (replaces `.rack-panel` cards): *silkscreen box*, not a raised card. `background: transparent` (or `rgba(255,255,255,0.35)` at most), `border: 1px solid rgba(26,26,46,0.14)`, radius **8px**, **no drop shadow**. Each frame gets a **group legend** sitting ON the top border, JV-style: an absolutely-positioned label at `top: -7px; left: 12px`, `padding: 0 6px`, `background: <faceplate color>` so it knocks out the border line. Legend text style per §2.3.
- **Inset well** (for LCD, keybed): recessed look — `box-shadow: inset 0 2px 6px rgba(20,30,60,0.18), inset 0 1px 2px rgba(20,30,60,0.12)`, border `1px solid rgba(26,26,46,0.18)`, radius **6px**.
- **Seams**: horizontal hairline between faceplate zones (brand strip / control zone / keybed zone): `border-top: 1px solid rgba(26,26,46,0.10)` plus `box-shadow: 0 1px 0 rgba(255,255,255,0.7)` for the machined-groove highlight.
- **Rack ears** (desktop ≥1024px only): 28px-wide strips flanking the chassis, slightly darker (`#DDE1E8`), each with two vertically-slotted screw holes (a 10px screw circle containing a 1×6px dark slot, rotated ~20deg). Hidden on mobile.
- **Screws**: keep the existing `.rack-screw` radial gradient; add a slot line inside (`::after`, 1px × 60% width dark bar, arbitrary rotation per corner) so they read as screws not dots.

### 2.2 Color roles

Keep every existing token; change *roles*, add legend + LCD tokens.

| Role | Token | Value | Notes |
|---|---|---|---|
| Faceplate top | `--color-face-hi` | `#F2F4F7` | chassis gradient stops |
| Faceplate bottom | `--color-face-lo` | `#E9ECF1` | |
| Hairline / silkscreen frame | `--color-hairline` | `rgba(26,26,46,0.14)` | group boxes, dividers |
| Legend (silkscreen text) | `--color-legend` | `#5A6172` | **4.9:1 on #FAFBFC — AA** |
| Legend strong (values, active) | `--color-legend-strong` | `#3C4356` | 8.6:1 |
| LCD glass | `--color-lcd-bg` | `#07211F` | deep blue-green black (was navy `#0F1024`) |
| LCD phosphor | `--color-lcd-text` | `#55E6C8` | **teal — used ONLY inside the LCD** |
| LCD dim | `--color-lcd-dim` | `#1D5B50` | secondary LCD rows |
| Primary accent / power | `--color-coral` | `#FF6B6B` (existing) | power LED, active-state LEDs, SAVE |
| Action accent | `--color-sky` | `#5BC0EB` (existing) | knob arcs, BROWSE, pressed keys |
| OK / cached | `--color-lime` | existing | status LEDs only |
| Remaining accents (amber, lavender, rose, mint, peach) | existing | | patch swatches, per-FX knob rings + LEDs **only** — never headings, never fills |

Rules: **sky-blue is no longer allowed inside the LCD** (that's the point of the teal); accent colors never fill a button face; glows (`box-shadow` blooms) only on *lit* LEDs and LCD text, never on idle chrome.

### 2.3 Typography roles

Stack is locked: **Fredoka** display / **Inter** body / **JetBrains Mono** legends. Do not change fonts.

| Role | Face | Size / weight / tracking | Color | Usage |
|---|---|---|---|---|
| Brand | Fredoka 600 | 20px, `tracking-widest` | `--color-text` | "MODULE" lockup only |
| Display S | Fredoka 500–600 | 15–18px | `--color-text` | picker titles, patch card names, modals |
| Body | Inter 400/500 | 13–14px | `--color-text` | descriptions, dialogs |
| **Legend** | JetBrains Mono 500 | **10px**, uppercase, `letter-spacing: 0.12em` | `--color-legend` | ALL silkscreen: group titles, knob labels, hints, chain map, HUD |
| **Legend strong** | JetBrains Mono 600 | **11px**, uppercase, `letter-spacing: 0.10em` | `--color-legend-strong` | live values (OCT 4, VEL 100), active-state labels, counts |
| LCD | JetBrains Mono 500 | 20–22px main row, 11px meta rows | LCD tokens | inside the display only |

Kill all 9px text (there are `text-[9px]` uses in `App.tsx`, `ButtonBank.tsx`, `Knob.tsx`, `TouchKeyboard.tsx`, `ValueDial.tsx`, `KeyboardHud.tsx` `.hud-kbd`) → 10px minimum. Kill all `text-text/40`–`/65` legends → the two legend tokens. Implement as two utility classes in `index.css` (e.g. `.legend` and `.legend-strong`) and sweep components onto them so the discipline is structural, not per-instance.

### 2.4 Hardware component language

- **Function button**: h 30–36px, radius **4px**, face `linear-gradient(180deg, #FFFFFF, #F0F2F6)`, border `1px solid #C9CFD9`, `box-shadow: 0 1px 0 rgba(255,255,255,0.9) inset, 0 1px 2px rgba(20,30,60,0.12)`. Pressed: `translateY(1px)` + `box-shadow: inset 0 2px 3px rgba(20,30,60,0.18)`. **Active = LED, not fill**: a 5px dot in the button's top-right (or a 3px lit bar along the top edge), coral, `box-shadow: 0 0 5px` bloom; face stays light, label switches to `--color-legend-strong`. Labels inside buttons are legend-style mono 10px.
- **Accent button** (BROWSE, SAVE — the "4x EXPANSION" allowance): same construction, but with a thin colored keyline (`box-shadow: inset 0 0 0 1.5px var(--color-sky|coral)`) and colored legend text + LED. **Not** a gradient fill bar.
- **Knob**: keep conic arc; add **detent ticks** — a `repeating-conic-gradient` ring of 11 hairline marks behind the arc (1px marks, `rgba(26,26,46,0.25)`), cap gets a crisper machined edge (`inset 0 0 0 1px rgba(20,30,60,0.10)` added to existing shadows). Label below in `.legend`; value-on-drag in `.legend-strong`.
- **VALUE rotary**: knurled rim via `repeating-conic-gradient(rgba(20,30,60,0.16) 0deg 3deg, transparent 3deg 7deg)` masked to the outer 10px annulus; matte cap; position mark = 3px×14px `#3C4356` bar (drop the coral glow); a static tick ring (dots every 30°) printed on the *panel* around the knob; legend "VALUE" printed *above* the knob (JV places it above), hint "drag · scroll" below in `.legend`.
- **LED**: sizes 5px (in-button), 8px (status). Off: `rgba(20,30,60,0.15)` + `inset 0 1px 1px rgba(0,0,0,0.2)`. On: solid accent + `0 0 6px` bloom + existing `.led-pulse` where idle-lit. Always paired with an adjacent silkscreen legend, never floating.
- **LCD**: recessed bezel = outer frame div (`#CBD1DA` gradient border, radius 6px, `inset` well shadow) around the glass (radius 3px). Glass keeps scanlines; add faint vignette `radial-gradient(ellipse at center, transparent 55%, rgba(0,0,0,0.35) 100%)`.

### 2.5 Spacing & rhythm

4px base grid. Group-frame padding **12px** (14–16px desktop); gap between frames **10px** (denser than today's 16px — rack modules are dense); intra-group control gap 6–8px; legend-to-control gap 4px. Radii scale: chassis 10 / group frame 8 / inset well 6 / button+LCD glass 4 / LED full.

### 2.6 Motion

Mechanical, small, fast. Button press: `translateY(1px)` + inset shadow, 80ms ease-out (replace `scale(0.94)` on hardware buttons; keep `.cell-hit` scale for picker cards). LED: instant on, 120ms decay off; keep `led-pulse` 1.6s for idle-lit status. LCD text changes: optional single 60ms opacity dip (refresh flicker) on patch change — subtle, skip if it reads as jank. No springy overshoot on faceplate hardware (keep `pop-in` for modals/picker only).

## 4. Non-goals / guardrails

- **Do not go dark.** "Light-colored cues" means the JV's *language* (legends, LEDs, bezels, density) on a light alloy surface. The only dark surfaces allowed: LCD glass, keybed, black keys.
- **Do not break the light theme or introduce `prefers-color-scheme` branching.** `color-scheme: light` stays.
- **Do not swap the font stack.** Fredoka/Inter/JetBrains Mono are locked; the pass tightens their roles.
- **Legends must stay ≥ WCAG AA (4.5:1).** `--color-legend: #5A6172` on `#FAFBFC` is the floor; never reintroduce sub-`/60` opacity text for meaning-bearing labels. Disabled/decorative-only text may go lighter but must not carry information alone.
- **Do not regress the mobile picker fixes** (header wrap, labelled download pills, offline pill) — Item 9 is token-only there. Re-verify against the existing scratchpad screenshots.
- **Color = state.** No accent fills on idle chrome, no glows on unlit elements, sky-blue never inside the LCD, teal never outside it.
- **Do not touch interaction logic** — pointer capture in `Knob`/`ValueDial`/`TouchKeyboard`, `data-midi` hit-testing, the first-gesture audio unlock, and store wiring are all load-bearing; this pass is presentation-only. Any new overlay inside the keybed must be `pointer-events: none`.
- **No literal Roland trade dress**: no Roland/JV logos or verbatim model strings; "MDL-1080"-style designations are homage, not imitation.
- **Keep contextual class names** (`rack-*`, `lcd-*`, `effect-pedal-*`, …) alongside Tailwind utilities on every element added or changed — this is a house rule.
